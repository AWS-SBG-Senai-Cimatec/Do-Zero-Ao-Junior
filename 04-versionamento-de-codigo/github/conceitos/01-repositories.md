# Repositórios no GitHub

## O que é um repositório?

Um repositório, ou *repository*, é o espaço onde ficam os arquivos de um projeto e o histórico das mudanças feitas neles. No GitHub, ele também funciona como um ponto central para a equipe compartilhar o código, acompanhar tarefas e colaborar.

O Git registra as alterações ao longo do tempo. O GitHub hospeda esse repositório na nuvem e oferece recursos para que outras pessoas trabalhem no projeto.

## Repositório público ou privado?

A visibilidade define quem pode acessar o conteúdo do repositório.

- **Público:** qualquer pessoa pode visualizar o conteúdo. É útil para projetos de portfólio e de código aberto.
- **Privado:** o acesso fica restrito às pessoas autorizadas. É mais adequado para projetos internos, código proprietário ou trabalho confidencial.

Deixar um repositório público não significa que outras pessoas têm permissão automática para reutilizar o código. Essa permissão é definida pela licença. Também não se deve enviar senhas, tokens ou outros dados confidenciais ao repositório.

## Por que a licença importa?

A licença informa o que outras pessoas podem fazer com o software, como copiar, modificar e distribuir o código. Sem uma licença, o código continua protegido por direitos autorais; outras pessoas podem visualizá-lo, mas não recebem automaticamente permissão para reutilizá-lo.

Algumas licenças comuns são:

- **MIT:** permissiva e simples. Permite usar, modificar e distribuir o código, desde que os avisos de direitos autorais e a licença sejam mantidos.
- **Apache 2.0:** também permissiva e inclui termos relacionados a patentes.
- **GPL:** licença *copyleft*. Em geral, distribuições de versões modificadas devem seguir os termos da GPL.

A escolha depende dos objetivos do projeto e das regras da organização ou dos colaboradores. Em caso de dúvida em um projeto profissional, consulte a política da equipe.

## Para que serve o README?

O `README.md` costuma ser a primeira página que alguém encontra ao abrir um repositório. Ele apresenta o projeto e ajuda outras pessoas a entender como começar.

Um README útil pode incluir:

- nome e descrição do projeto;
- objetivo e principais recursos;
- instruções de instalação e execução;
- exemplo de uso;
- dependências necessárias;
- formas de contribuir;
- licença e informações de contato, quando aplicáveis.

## Checklist antes de publicar

- [ ] Escolher a visibilidade adequada ao projeto.
- [ ] Verificar se não há senhas, tokens ou informações confidenciais.
- [ ] Adicionar uma licença compatível com o uso pretendido.
- [ ] Escrever um README com instruções claras para começar.
- [ ] Conferir se os arquivos enviados são os corretos.
